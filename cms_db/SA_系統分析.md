## 2. 系統情境（System Context）

CMS 位於封閉式 Web 應用的核心，作為唯一資料來源 `cms_db` 的存取層。

```
                      ┌──────────────────────────────┐
  管理者 / 編輯 ─────►│                              │
  作者 ────────────►│                              │
                      │            CMS 系統           │◄──── cms_db (MySQL 8.0)
  訂閱者 ──────────►│      (Web Application)       │
                      │                              │
  未登入訪客 ──────►│                              │
                      └──────────────────────────────┘
```

### 2.1 外部參與者（Actor）

| 參與者 | 型別 | 說明 |
|---|---|---|
| 訪客（Guest） | 未登入 | 瀏覽已發佈文章、以姓名／信箱留言 |
| 訂閱者（subscriber） | 登入 | 瀏覽文章、發表留言 |
| 作者（author） | 登入 | 建立／編輯自己的文章（草稿／待審） |
| 編輯（editor） | 登入 | 撰寫文章、審核文章與留言、管理分類標籤 |
| 管理者（admin） | 登入 | 上述全部 + 使用者管理、角色指派 |
| 系統（System） | 非人 | 時間排程備份、自動記錄時間與狀態 |

### 2.2 與外部系統之邊界

| 項目 | 邊界 | 說明 |
|---|---|---|
| 電子商務／金流 | 範圍外 | 不涉及 |
| 前端版型 Template 管理 | 範圍外 | 不提供 |
| 多語系翻譯管理 | 範圍外 | 不提供 |
| 對外 API／RSS | 範圍外 | 首期不提供 |
| 全文檢索引擎 | 範圍外 | 以資料庫 Like／索引檢索取代 |

### 4.2 使用案例詳述

#### UC-01 使用者註冊

| 項目 | 內容 |
|---|---|
| 參與者 | 訪客 |
| 前置條件 | 無 |
| 主流程 | 1. 訪客輸入 `username`、`email`、`password`，確認密碼。<br>2. 系統驗證帳號／信箱格式與唯一性。<br>3. 系統以 BCrypt 產生 `password_hash`。<br>4. 系統依 FR-01-04 指派預設角色 `author`。<br>5. 系統寫入 `users` 並回傳成功。 |
| 替代流程 | 2a. `username` 或 `email` 已存在 → 回傳明確錯誤，不產生紀錄。 |
| 後置條件 | 產生新的 `author` 使用者紀錄 |
| 對應需求 | FR-01-01 ~ FR-01-04, FR-01-07 |

#### UC-02 登入／登出

| 項目 | 內容 |
|---|---|
| 參與者 | 所有角色、訪客 |
| 主流程 | 1. 輸入 `username` + `password`。<br>2. 系統比對 `password_hash`。<br>3. 建立認證階段（Session／Token），載入角色權限。<br>4. 登出時銷毀認證狀態。 |
| 替代流程 | 2a. 帳號停用 → 拒絕登入。<br>2b. 密碼錯誤 → 回傳錯誤，必要時限流。 |
| 對應需求 | FR-01, NFR-02 |

#### UC-03 瀏覽與篩選已發佈文章

| 項目 | 內容 |
|---|---|
| 參與者 | 訪客、訂閱者、所有角色 |
| 主流程 | 1. 依分頁展示 `status = published` 之文章。<br>2. 依分類、標籤、關鍵字或時間篩選。<br>3. 進入文章詳情時累計 `view_count`。 |
| 後置條件 | `view_count` 於詳情瀏覽時 +1 |
| 對應需求 | FR-02-08, FR-03, FR-04 |

#### UC-04 發表留言

| 項目 | 內容 |
|---|---|
| 參與者 | 登入使用者、訪客 |
| 前置條件 | 目標文章存在 |
| 主流程（登入） | 1. 於文章頁送出留言內容。<br>2. 系統記錄 `user_id`，`status` 預設 `pending`。<br>3. 回覆留言時設定 `parent_id`。 |
| 主流程（訪客） | 1. 輸入 `author_name`、`author_email` 與內容。<br>2. 系統寫入留言，`user_id = NULL`，`status = pending`。 |
| 後置條件 | 新增一筆 `pending` 留言；審核通過前不對一般使用者顯示 |
| 對應需求 | FR-05-01 ~ FR-05-04 |

#### UC-05 建立文章（草稿）

| 項目 | 內容 |
|---|---|
| 參與者 | author、editor、admin |
| 前置條件 | 已登入且具建立權限（見矩陣） |
| 主流程 | 1. 輸入標題、摘要、內文、精選圖片。<br>2. 系統產生唯一 `slug`（由標題轉換或手動指定）。<br>3. 關聯多個分類／標籤。<br>4. 儲存為 `draft`，記錄 `author_id`。 |
| 對應需求 | FR-02-01, FR-02-02, FR-02-03, FR-02-06, FR-02-10 |

#### UC-06 編輯自己的文章

| 項目 | 內容 |
|---|---|
| 參與者 | author（自己的）、editor／admin（全部） |
| 主流程 | 1. 讀取文章。<br>2. 修改內容／分類／標籤。<br>3. 儲存；若原為 `draft` 則維持 `draft`。<br>4. 若為 `pending_review` 之退回，維持 `draft` 或 `pending_review`。 |
| 對應需求 | FR-02-05, NFR-02（防止存取他人草稿） |

#### UC-07 送交審核

| 項目 | 內容 |
|---|---|
| 參與者 | author、editor、admin |
| 前置條件 | 文章狀態為 `draft` |
| 主流程 | 將文章狀態由 `draft` 轉為 `pending_review`。 |
| 後置條件 | 進入等待審核佇列 |
| 對應需求 | FR-02-04 |

#### UC-08 審核文章

| 項目 | 內容 |
|---|---|
| 參與者 | editor、admin |
| 前置條件 | 文章狀態為 `pending_review` |
| 主流程 | 1. 讀取待審文章。<br>2. **核准**：狀態轉為 `published`，自動寫入 `published_at = 現在時間`。<br>3. **退回**：狀態轉為 `draft`（可附退回原因）。 |
| 後置條件 | 文章對一般使用者可見／不可見依據狀態決定 |
| 對應需求 | FR-02-05, FR-02-07 |

#### UC-09 管理分類（階層式）

| 項目 | 內容 |
|---|---|
| 參與者 | editor、admin |
| 主流程 | 建立／編輯／刪除分類；設定 `parent_id` 建立階層。 |
| 業務規則 | 1. `slug` 全域唯一。<br>2. 禁止將自身或子分類設為父分類（防形成循環）。<br>3. 刪除分類時依 FR-03-05 策略處理（規劃：有子類或已關聯文章時禁止刪除，或採轉移策略）。 |
| 對應需求 | FR-03-01 ~ FR-03-05 |

#### UC-10 管理標籤

| 項目 | 內容 |
|---|---|
| 參與者 | editor、admin |
| 主流程 | 建立／編輯／刪除標籤，扁平結構，`name`／`slug` 唯一。 |
| 對應需求 | FR-04-01 ~ FR-04-03 |

#### UC-11 審核留言

| 項目 | 內容 |
|---|---|
| 參與者 | editor、admin |
| 主流程 | 瀏覽 `pending` 留言 → 標記 `approved`（顯示）或 `spam`（隱藏）。 |
| 後置條件 | 一般使用者僅見 `approved`。 |
| 對應需求 | FR-05-05, FR-05-06 |

#### UC-12 管理使用者

| 項目 | 內容 |
|---|---|
| 參與者 | admin |
| 主流程 | 查詢使用者、變更角色、停用／啟用、刪除。 |
| 業務規則 | 停用後拒絕登入；刪除前須處理其文章（禁止刪除或轉移）。 |
| 對應需求 | FR-01-05, AC-02 |

#### UC-13 上傳多媒體

| 項目 | 內容 |
|---|---|
| 參與者 | author、editor、admin |
| 主流程 | 1. 上傳檔案。<br>2. 驗證 MIME 類型與大小（業務規則另行定義）。<br>3. 寫入 `media`，記錄 `uploader_id`、路徑、大小。<br>4. 可設 `alt_text`，供文章精選圖片或內文引用。 |
| 對應需求 | FR-06-01 ~ FR-06-05, NFR-02 |

#### UC-14 管理全部多媒體

| 項目 | 內容 |
|---|---|
| 參與者 | editor、admin（興審管理）；author 僅自己的 |
| 主流程 | 檢視／編輯 `alt_text`／刪除檔案。 |
| 對應需求 | FR-06, AC |

## 5. 系統流程分析

### 5.1 文章狀態流程（狀態圖）

```
                    ┌────────────────────────┐
                    ▼                        │
  ┌────────┐   送交審核   ┌──────────────┐   核准    ┌──────────┐
  │ draft  │ ───────────► │ pending_     │ ───────► │ published│
  │ 草稿   │              │ review 待審  │ ◄─────── │ 已發佈   │
  └────────┘              └──────────────┘   退回    └──────────┘
       ▲                       │                             │
       │       退回（draft）   │          封存               │
       └──────────────────────┘                             ▼
                                                ┌──────────────┐
                                                │ archived     │
                                                │ 已封存（隱藏） │
                                                └──────────────┘
```

| 轉移 | 觸發者 | 動作條件 | 備註 |
|---|---|---|---|
| draft → pending_review | author/editor/admin | 文章作者或具權限者 | FR-02-04 |
| pending_review → published | editor/admin | 核准，自動寫 `published_at` | FR-02-05, FR-02-07 |
| pending_review → draft | editor/admin | 退回 | FR-02-05 |
| published → archived | editor/admin | 封存，對一般使用者隱藏 | FR-02-09 |
| archived → published | editor/admin | 重新發佈 | FR-02-09（重新上架） |

### 5.2 留言審核流程

```
訪客/登入使用者送出留言 → status = pending
        │
        ▼
 editor/admin 審核 ────► approved（一般使用者可見）
        │
        ├──────────────► spam（標記垃圾，隱藏）
        └──────────────► （可維持 pending 或刪除）
```

### 5.3 分類階層規則

- 根節點：`parent_id IS NULL`
- 防止循環：`parent_id != id`，且 `parent_id` 不得為自身的任一子節點。
- 刪除策略（FR-03-05）建議採「**受限刪除**」：
  1. 分類下存在子分類 → 禁止刪除（須先處理子分類）。
  2. 分類已關聯文章 → 禁止刪除（或改為「轉移至指定分類」）。
  3. 均無 → 直接刪除並移除中介表關聯。

### 5.4 錯誤與異常情境

| 情境 | 系統行為 |
|---|---|
| `slug` 重複（文章／分類／標籤） | 回傳欄位錯誤，提示使用者修改，不寫入 |
| 存取他人草稿 | 回傳 403，禁止讀取 |
| 停用帳號登入 | 拒絕登入並提示 |
| 未經審核留言展示 | 不顯示（僅查 `approved`） |
| 上傳非法格式／超限檔案 | 拒絕並回傳錯誤 |
| FK 違例（孤立紀錄） | 資料庫層級攔截，不產生孤兒資料 |

## 6. 資料模型分析

### 6.1 實體與關係（ER 摘要）

```
users 1 ──< N articles              （articles.author_id → users.id）
users 1 ──< N comments              （comments.user_id → users.id）
users 1 ──< N media                 （media.uploader_id → users.id）
articles 1 ──< N comments           （comments.article_id → articles.id）
articles N >──< M categories        （中介表 article_categories）
articles N >──< M tags              （中介表 article_tags）
categories N ──< 1 categories       （自我關聯 parent_id）
comments  N ──< 1 comments          （自我關聯 parent_id）
```

### 6.2 實體清單

| 實體 | 型別 | 關鍵規則 |
|---|---|---|
| users | 強實體 | `username`、`email` 唯一 |
| articles | 強實體 | `slug` 唯一，`status` 列舉，依 `author_id` 依賴 users |
| categories | 強實體（自我關聯） | `slug` 唯一，`parent_id` 自參 |
| tags | 強實體 | `name`、`slug` 唯一 |
| comments | 強實體（自我關聯） | `status` 列舉，`user_id` 或訪客欄位二擇一 |
| media | 強實體 | 依附 `uploader_id` |
| article_categories | 中介實體 | 複合主鍵 (article_id, category_id) |
| article_tags | 中介實體 | 複合主鍵 (article_id, tag_id) |

### 6.3 資料完整性分析

| 規則 | 說明 | 對應需求 |
|---|---|---|
| 唯一索引 | 見 §5.3 需求「資料完整性規則」 | FR-01-02, FR-03-01, FR-04-01 |
| 必填欄位 | `password_hash`、文章 `content`、留言 `content` 不可 NULL | FR-01-03, FR-02, FR-05 |
| 參照完整性 | 全 FK 於 DB 層強制 | 5.3 |
| 串聯刪除 | 文章刪除 CASCADE 中介表關聯；分類／標籤刪除連帶移除關聯 | 5.3, AC-06 |
| 留言合法性 | 登入與訪客身份二選一（`user_id` 非空時 `author_name/email` 可不填） | FR-05-01 |

## 7. 非功能性需求分析（落實指引）

| NFR | 分析結果 | 落實方向 |
|---|---|---|
| NFR-01 效能 ≤ 2 秒 | 熱門查詢集中在 `articles`（status、title、author_id、slug），及中介表 | 建立複合索引與必要索引；前端分頁 |
| NFR-02 安全 | 密碼 BCrypt、權限檢查、SQL/XSS 注入防護、上傳驗證 | 後端框架提供防護，一律服務端驗證 |
| NFR-03 備援復原 | 每日備份保留 7 日，RTO ≤ 4h、RPO ≤ 1 day | DB 排程備份 + DR 演練 |
| NFR-04 擴充性 | 內文與靜態資源分離；媒體採本機磁碟或物件儲存 | 儲存抽象層設計 |
| NFR-05 可用性 | ≥ 99.5%，繁體中文介面 | 部署多實例 + 健康檢查 |

## 9. 分析結論與設計輸入

SA 階段分析確認下列設計輸入，交由 SD 階段展開：

1. 6 個功能模組（auth/users、articles、categories、tags、comments、media）。
