---

## 1. 系統概述

本系統為一間餐廳的**銷售點（POS）管理系統**，提供：員工登入管理、桌位管理、菜單管理、點餐（訂單明細）、結帳收款與每日結帳報表等功能。系統以單一 MySQL 資料庫 `restaurant_pos` 儲存所有交易資料。

系統核心流程如下：

```
員工登入 → 桌位開單 → 選菜點餐 → 加點/客製 → 結帳付款 → 每日結帳
```

## 2. 系統範圍

本系統涵蓋下列模組：

| 編號 | 模組 | 對應資料表 |
| --- | --- | --- |
| M1 | 員工管理 | `employee` |
| M2 | 桌位管理 | `restaurant_table` |
| M3 | 菜單管理 | `menu_item` |
| M4 | 點餐管理 | `orders`、`order_item` |
| M5 | 結帳付款 | `payment`、`orders` |
| M6 | 每日結帳 | `daily_closing` |

## 3. 使用者與角色

系統依 `employee.role` 區分兩種角色：

| 角色 | 說明 | 主要權限 |
| --- | --- | --- |
| ADMIN | 管理者 | 全部功能：員工管理、菜單管理、每日結帳等 |
| STAFF | 一般員工 | 桌位開單、點餐、結帳作業 |

每位員工以唯一 `username`（登入帳號）識別，並有 `active` 欄位控制是否可登入使用。

## 4. 功能需求

### FR-01 員工管理（M1）
1. 系統須能新增員工帳號，包含帳號、密碼、姓名與角色。
2. 帳號（`username`）為唯一值，不可重複。
3. 員工可被停用（`active=0`）或啟用（`active=1`），停用後無法登入。
4. 系統須記錄員工建立時間（`created_at`）與異動時間（`updated_at`）。

### FR-02 桌位管理（M2）
1. 桌號（`table_number`）為唯一值，不可重複。
2. 每桌須設定容納人數（`capacity`）。
3. 桌位具有狀態（`status`），目前檔內資料值為 `AVAILABLE`（可用），系統須可擴充其他狀態（如占用 OCCUPIED）。
4. 系統須記錄桌位建立與異動時間（`created_at`、`updated_at`）。

### FR-03 菜單管理（M3）
1. 菜單項目包含名稱、分類、單價、上架狀態與描述。
2. 分類（`category`）檔內資料含 `FOOD`（餐點）、`DRINK`（飲料）兩類。
3. 菜單項目可設定是否可供販售（`available`：1 可販售 / 0 停售）。
4. 系統須記錄菜單建立與異動時間。

### FR-04 點餐管理（M4）
1. 開單時須指定桌位（`table_id`）與開單員工（`employee_id`），訂單狀態預設為 `OPEN`（開單中）。
2. 同一張訂單可包含多筆明細（`order_item`），每筆明細對應一個菜單項目。
3. 每筆明細須記錄數量（`quantity`）、當時單價（`unit_price`）與小計（`subtotal = unit_price × quantity`）。
4. 飲料類明細可指定客製化選項：**糖度**（`sugar_level`，如「半糖」）與 **冰塊**（`ice_level`，如「微冰」），亦可有備註（`note`）。
5. 訂單狀態檔內資料含 `OPEN`（預設）、`PAID`（已付款）、`CANCELLED`（已取消）。
6. 訂單總金額（`total_amount`）預設為 0，系統須於點餐/結帳時更新。
7. 系統須記錄訂單建立、異動及付款時間（`created_at`、`updated_at`、`paid_at`）。

### FR-05 結帳付款（M5）
1. 一張訂單只能完成一次付款（`payment.order_id` 為唯一值）。
2. 付款方式（`payment_method`）檔內資料含：`CASH`（現金）、`CREDIT_CARD`（信用卡）、`LINE_PAY`（Line Pay）。
3. 付款須記錄收款金額（`amount`）、收款員工（`employee_id`）與付款時間（`paid_at`）。
4. 付款完成後，訂單狀態應更新為 `PAID`，並記錄 `paid_at`。

### FR-06 每日結帳（M6）
1. 系統每日可執行結帳，產生結帳日報。
2. 每個日期（`closing_date`）只能有一筆結帳紀錄（唯一值）。
3. 結帳報表須包含：該日訂單數（`total_orders`）、總營收（`total_revenue`）、各付款方式金額（現金 `cash_amount`、信用卡 `card_amount`、其他 `other_amount`）。
4. 結帳須記錄執行的員工（`employee_id`）與執行時間（`closed_at`）。
5. 依檔內資料，`other_amount` 可含 Line Pay 等非現金/非信用卡之收款。

## 5. 資料需求（資料庫設計）

### 5.1 實體關係圖（ER Model）

```
employee ──< orders >── order_item >── menu_item
              │   │
              │   └── payment
              │
restaurant_table >── orders
employee ──< daily_closing
employee ──< payment
```

關聯說明：
- 一位員工可開多張訂單（`employee 1 ──< orders`）
- 一張桌位可有多張訂單（`restaurant_table 1 ──< orders`）
- 一張訂單有多筆明細（`orders 1 ──< order_item`）
- 一個菜單項目可被多筆明細引用（`menu_item 1 ──< order_item`）
- 一張訂單至多一筆付款（`orders 1 ── 1 payment`）
- 一個員工可收多筆款、可執行多次結帳

## 6. 業務規則（BR）

| 編號 | 規則 |
| --- | --- |
| BR-01 | `order_item.subtotal = unit_price × quantity`。 |
| BR-02 | `orders.total_amount` 應等於該訂單所有明細 `subtotal` 之加總。 |
| BR-03 | 一筆 `order_id` 至多對應一筆 `payment`（唯一鍵限制）。 |
| BR-04 | 訂單付款後狀態由 `OPEN` 轉為 `PAID`，並寫入 `paid_at`。 |
| BR-05 | `daily_closing.total_orders` 應等於該日 `PAID`（非取消）訂單數。 |
| BR-06 | `cash_amount + card_amount + other_amount = total_revenue`。 |
| BR-07 | 飲料類（`DRINK`）明細可填寫糖度 `sugar_level`、冰塊 `ice_level`。 |

## 7. 非功能需求（NFR）

| 編號 | 需求 |
| --- | --- |
| NFR-01 | 資料庫採 MySQL 8.0 InnoDB，字元集 `utf8mb4`、`utf8mb4_unicode_ci`，支援中文。 |
| NFR-02 | 金額欄位採 DECIMAL 精確型別（價格 `decimal(10,2)`、營收 `decimal(12,2)`），避免浮點誤差。 |
| NFR-03 | 所有對外鍵（FK）的刪除均設有約束，保護交易資料完整性。 |
| NFR-04 | 員工密碼應以雜湊方式儲存（欄位長 255，供存放密碼雜湊）。 |
| NFR-05 | 系統須使用 UTC+8（台灣）時區顯示交易與結帳時間。 |
| NFR-06 | `orders`、`order_item`、`payment` 等交易資料應保留完整歷史紀錄，不得實體刪除。 |
| NFR-07 | 提供交易與結帳之查詢/報表能力，供管理者核帳。 |
