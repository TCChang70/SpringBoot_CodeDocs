# 點餐系統後端 — 階段驗收式實作測驗（考生卷 v3）

| 項目 | 說明 |
|------|------|
| 主題 | 點餐系統 Backend API（Spring Boot + JPA + MySQL） |
| 形式 | **階段驗收式（TDD 風格）**：系統拆成 8 個階段，每階段給你「目標＋驗收測試」，你用程式碼讓驗收綠燈後才進入下一階段 |
| 技術棧 | Spring Boot 3.2 / Java 17 / Maven / Spring Data JPA / MySQL / JUnit 5 |
| 建議時間 | 150 分鐘（含每階段驗收執行時間） |

---

## 作答規則

1. **依階段順序完成，每一階段完成後先跑驗收，再進入下一階段**（階段之間有依賴，跳關會卡住）。
2. 各階段會提供：
   - **目標**：這個階段要交出什麼。
   - **需求重點**：該做的事（不給完整解答，自己實作）。
   - **驗收**：要執行的測試程式碼或指令，**全部綠燈＝階段完成**。
   - **提交物**：每階段結束後要準備的交付內容（寫進你的提交清單）。
3. `git commit` 建議每個階段一次，commit message 用階段編號（例：`stage-3: repository`），作為逐階段提交的證明。
4. 基礎設施類設定（pom、application.properties、CORS、init.sql）由題目完整提供——它們不是考點，是讓你能往前走的環境。
5. 業務邏輯（Entity/Repository/Service/Controller/例外）要**自己寫**，只有測試是驗收關卡。
6. 優異門檻包含第 13 階段（階段 8）加分題。

## 階段地圖

| 階段 | 主題 | 驗收方式 | 配分 |
|------|------|----------|------|
| 0 | 環境與專案骨架 | `mvn spring-boot:run` 啟動 | 10 |
| 1 | 資料庫 schema 與種子 | SQL 結果 | 10 |
| 2 | 實體層 Entity | `mvn test`（SchemaProbeTest） | 15 |
| 3 | Repository 查詢 | `mvn test`（MenuItemRepositoryIT） | 15 |
| 4 | DTO 與全域例外 | `mvn test`（ApiContractTest） | 10 |
| 5 | Service 交易 | `mvn test`（OrderServiceIT 回滾驗證） | 15 |
| 6 | Controller 與 CORS | cURL 全端點 | 15 |
| 7 | Dashboard 與總驗收 | cURL + 加分題 | 10 |
| 8 | 加分題（選做） | 展示與說明 | +10 |
| | | **合計** | **100 + 10** |

> 及格門檻：**60 分**。每階段「驗收綠燈」才計算該階段配分（未綠燈該階段 0 分）。

# 階段 1．資料庫 schema 與種子

## 目標

## 需求重點

- 建立 `food_order`（utf8mb4）資料庫。
- 用下方 `init.sql` 建三張表＋6 筆種子。
- 完成 `application.properties`（MySQL 連線、JPA `ddl-auto=none`）。

## 提供的檔案

`init.sql`（完整，直接執行）：

```sql
CREATE DATABASE IF NOT EXISTS food_order
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE food_order;

CREATE TABLE IF NOT EXISTS menu_items (
    id             BIGINT AUTO_INCREMENT PRIMARY KEY,
    name           VARCHAR(80)   NOT NULL,
    category       VARCHAR(30)   NOT NULL,
    price          DECIMAL(10,2) NOT NULL,
    is_available   TINYINT(1)    NOT NULL DEFAULT 1,
    stock_quantity INT           NOT NULL DEFAULT 0
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS orders (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    customer_name VARCHAR(50)  NOT NULL,
    order_time    DATETIME     NOT NULL,
    status        VARCHAR(20)  NOT NULL DEFAULT 'PENDING',
    total_amount  DECIMAL(10,2) NOT NULL DEFAULT 0.00
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS order_items (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    order_id      BIGINT        NOT NULL,
    menu_item_id  BIGINT        NOT NULL,
    quantity      INT           NOT NULL,
    unit_price    DECIMAL(10,2) NOT NULL,
    CONSTRAINT fk_oi_order FOREIGN KEY (order_id)     REFERENCES orders(id),
    CONSTRAINT fk_oi_menu  FOREIGN KEY (menu_item_id) REFERENCES menu_items(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

# 階段 2．實體層 Entity

## 目標

三個 Entity 對應三張表，讓 `SchemaProbeTest` 綠燈 = 實體映射正確。

## 需求重點

依下方三張欄位表自行撰寫 `com.example.order.model` 三個類別：

**MenuItem → `menu_items`**

| Java 欄位 | 資料表欄位 | 型別 | 約束 |
|-----------|-----------|------|------|
| id | id | Long | `@Id` + IDENTITY |
| name | name | String | length 80、nullable=false |
| category | category | String | length 30、nullable=false |
| price | price | BigDecimal | nullable=false |
| available | is_available | boolean | 預設 true |
| stockQuantity | stock_quantity | int | — |

**Order → `orders`**

| Java 欄位 | 資料表欄位 | 型別 | 約束 |
|-----------|-----------|------|------|
| id | id | Long | `@Id` + IDENTITY |
| customerName | customer_name | String | length 50、nullable=false |
| orderTime | order_time | LocalDateTime | nullable=false |
| status | status | String | 預設 "PENDING" |
| totalAmount | total_amount | BigDecimal | nullable=false |
| items | （無欄位） | List\<OrderItem\> | `@OneToMany(mappedBy="order", cascade=ALL, orphanRemoval=true)` |

**OrderItem → `order_items`**

| Java 欄位 | 資料表欄位 | 型別 | 約束 |
|-----------|-----------|------|------|
| id | id | Long | `@Id` + IDENTITY |
| order | order_id | Order | `@ManyToOne` + `@JoinColumn(name="order_id")` |
| menuItem | menu_item_id | MenuItem | `@ManyToOne` + `@JoinColumn(name="menu_item_id")` |
| quantity | quantity | int | nullable=false |
| unitPrice | unit_price | BigDecimal | nullable=false |

其他要求：

- 每個類別都要無參數建構子（JPA 需要）與 Getter/Setter。
- `Order` 提供 `addItem(OrderItem)`：加進集合並 `item.setOrder(this)`（維持雙向一致）。
- `OrderItem` 提供 `getSubtotal()`：`unitPrice × quantity`。
- 金額一律 `BigDecimal`（浮點誤差原因見階段 3 附註）。
- 不可把 `price` 寫成 `double`。

# 階段 3．Repository 查詢

## 目標

`MenuItemRepository`、`OrderRepository` 滿足以下方法簽名，`MenuItemRepositoryIT` 綠燈。

## 需求重點

**MenuItemRepository**（`extends JpaRepository<MenuItem, Long>`）：

```java
List<MenuItem> findByCategory(String category);                       // 依分類
List<MenuItem> findByAvailableTrue();                                 // 依供應狀態
List<MenuItem> findByStockQuantityAndAvailableTrue(int stockQuantity); // 售罄清單
List<MenuItem> searchByName(String keyword);                          // 名稱模糊搜尋
List<Object[]> findTopSellingItems();                                 // 熱賣排行
List<Object[]> getCategorySalesSummary();                             // 分類統計
```

**OrderRepository**（`extends JpaRepository<Order, Long>`）：

```java
List<Order> findByStatus(String status);
long countByStatus(String status);
BigDecimal sumCompletedAmount(LocalDateTime start, LocalDateTime end); // @Query：今日已完成營業額
long countByOrderTimeBetween(LocalDateTime start, LocalDateTime end); // @Query：今日訂單數
```

實作提示（答案邏輯，自訂實作）：

| 方法 | 建議寫法 |
|------|----------|
| `findByCategory` / `findByAvailableTrue` / `findByStockQuantityAndAvailableTrue` | Derived Query（靠方法命名自動實作） |
| `searchByName` | `@Query("SELECT m FROM MenuItem m WHERE LOWER(m.name) LIKE LOWER(CONCAT('%', :keyword, '%'))")`（不分大小寫模糊） |
| `findTopSellingItems` | JOIN `oi.menuItem`，`GROUP BY m.id, m.name ORDER BY SUM(oi.quantity) DESC`，SELECT `m.name, SUM(oi.quantity)` |
| `getCategorySalesSummary` | SELECT `m.category, COUNT(m.id), SUM(oi.quantity), SUM(oi.unitPrice*oi.quantity)` GROUP BY `m.category` |
| `countByStatus` | Derived Query 計數文法 `long countBy<欄位>` |
| `sumCompletedAmount` | `@Query("SELECT COALESCE(SUM(o.totalAmount),0) FROM Order o WHERE o.status='COMPLETED' AND o.orderTime BETWEEN :start AND :end")` |
| `countByOrderTimeBetween` | `@Query("SELECT COUNT(o) FROM Order o WHERE o.orderTime BETWEEN :start AND :end")` |

> JPQL 用的欄位名是 **Java 屬性名**（`m.name`），不是資料表欄位名。

## 附註：為什麼金錢用 BigDecimal

```
0.1 + 0.2 = 0.30000000000000004   ← IEEE 754 浮點
```

float/double 無法精確表示十進位小數，金錢運算會累積誤差。`BigDecimal` 是任意精度十進位，價格/小計/總額一律用它。
# 階段 4．DTO 與全域例外

## 目標

API 進出統一用 `ApiResponse<T>` 包裝；錯誤統一由 `GlobalExceptionHandler` 回傳結構化 JSON。`ApiContractTest` 綠燈。

## 需求重點

**dto/ApiResponse.java**（完整提供）：

```java
package com.example.order.dto;

public class ApiResponse<T> {
    private boolean success;
    private String  message;
    private T       data;

    public static <T> ApiResponse<T> ok(T data) {
        ApiResponse<T> res = new ApiResponse<>();
        res.success = true; res.message = "success"; res.data = data;
        return res;
    }
    public static <T> ApiResponse<T> ok(String message, T data) {
        ApiResponse<T> res = new ApiResponse<>();
        res.success = true; res.message = message; res.data = data;
        return res;
    }
    public boolean isSuccess() { return success; }
    public void setSuccess(boolean success) { this.success = success; }
    public String getMessage() { return message; }
    public void setMessage(String message) { this.message = message; }
    public T getData() { return data; }
    public void setData(T data) { this.data = data; }
}
```

**dto/MenuItemRequest.java**（驗證規則，自己寫好類別：name/category/price/available/stockQuantity）

| 欄位 | 驗證 |
|------|------|
| name | `@NotBlank`、長度 ≤ 80 |
| category | `@NotBlank` |
| price | `@DecimalMin(value="0", inclusive=false)` |
| stockQuantity | `@Min(0)` |
| available | boolean，預設 true，不需驗證 |

**dto/CreateOrderRequest.java**（巢狀明細，自己寫）

- `customerName`：`@NotBlank`
- `items`：`List<OrderItemRequest>`，必須 `@Valid` ＋`@NotEmpty`
- 內部類 `OrderItemRequest`：`menuItemId`（`@NotNull`）、`quantity`（`@NotNull`、`@Min(1)`）

**exception/ResourceNotFoundException**（`extends RuntimeException`，建構子吃 message）
**exception/StockNotEnoughException**（同上）
**exception/GlobalExceptionHandler**（`@RestControllerAdvice`）

| 例外 | HTTP | errorCode |
|------|------|-----------|
| ResourceNotFoundException | 404 | NOT_FOUND |
| StockNotEnoughException | 400 | STOCK_NOT_ENOUGH |
| IllegalArgumentException | 400 | BAD_REQUEST |
| MethodArgumentNotValidException | 400 | VALIDATION_ERROR（含 `errors` 物件） |

## 驗收

`src/test/java/com/example/order/dto/ApiContractTest.java`：

```java
package com.example.order.dto;

import com.example.order.exception.GlobalExceptionHandler;
import com.example.order.exception.ResourceNotFoundException;
import com.example.order.exception.StockNotEnoughException;
import jakarta.validation.ConstraintViolation;
import jakarta.validation.Validation;
import jakarta.validation.Validator;
import org.junit.jupiter.api.Test;
import org.springframework.http.ResponseEntity;

import java.util.Map;
import java.util.Set;

import static org.assertj.core.api.Assertions.assertThat;

class ApiContractTest {

    private final Validator validator = Validation.buildDefaultValidatorFactory().getValidator();

    @Test
    void ApiResponse_兩種多載皆可用() {
        assertThat(ApiResponse.ok("hi").isSuccess()).isTrue();
        assertThat(ApiResponse.ok("created", 123).getData()).isEqualTo(123);
    }

    @Test
    void MenuItemRequest_價格必須大於0() {
        MenuItemRequest req = new MenuItemRequest();
        req.setName("");            // @NotBlank 也會失敗
        req.setCategory("主餐");
        req.setPrice(java.math.BigDecimal.valueOf(0));  // 違反 >0
        Set<ConstraintViolation<MenuItemRequest>> violations =
                validator.validate(req);
        assertThat(violations).isNotEmpty();
        assertThat(violations).anyMatch(v -> v.getMessage().contains("價格"));
    }

    @Test
```

# 階段 5．Service 交易

## 目標

`OrderService.createOrder` 是「一個交易」：任何一步失敗整單回滾。`OrderServiceIT` 綠燈（含庫存不變的證明）。

## 需求重點

建立兩個 Service：

**MenuItemService**（`@Service`）— CRUD＋篩選＋搜尋＋售罄，方法簽名自由，包含：
- `findAll` / `findByCategory` / `findAvailable` / `search(keyword)` / `findSoldOut`
- `findById(id)`（找不到丟 `ResourceNotFoundException`）
- `create(req)` / `update(id, req)` / `delete(id)`
- 查詢方法加 `@Transactional(readOnly = true)`

**OrderService**（`@Service`）— 核心商業邏輯：

```java
public Order createOrder(CreateOrderRequest req)
public List<Order> findAll()
public Order findById(Long id)
public List<Order> findByStatus(String status)
public Order updateStatus(Long id, String status)
public Map<String, Object> getDashboard()
```

`createOrder` 演算法（自己實作）：

1. 建 `Order`：customerName、`orderTime = LocalDateTime.now()`、status="PENDING"、`total = BigDecimal.ZERO`。
2. 依序處理每筆明細（**上面掛 `@Transactional`**）：
   - 找不到菜單 → `ResourceNotFoundException`
   - `!menu.isAvailable()` → `StockNotEnoughException("已停售: ...")`
   - `menu.getStockQuantity() < 需求量` → `StockNotEnoughException("庫存不足: 名稱 (剩 N)")`
   - **扣庫存**：`menu.setStockQuantity(...)` 後 `save()`
   - **價格快照**：`OrderItem.unitPrice = menu.getPrice()`（不是日後價格）
   - `order.addItem(...)`、`total = total.add(getSubtotal())`
3. `order.setTotalAmount(total)`；`orderRepo.save(order)`（`cascade` 會連明細一起存）。

`getDashboard` 回傳 Map：`topSelling`（熱賣排行 List\<Map\>）、`todayRevenue`（今日 COMPLETED 營業額）、`pendingOrders`（`countByStatus("PENDING")`）、`todayOrders`（今日訂單數）。

> 為什麼必須 `@Transactional`：扣庫存與建訂單若拆成兩次 commit，中途失敗會「庫存已扣、訂單不存在」，資料就對不上。交易保證一起成功或一起回滾。

## 驗收

`src/test/java/com/example/order/service/OrderServiceIT.java`：

```java
package com.example.order.service;

import com.example.order.dto.CreateOrderRequest;
import com.example.order.exception.StockNotEnoughException;
import com.example.order.model.MenuItem;
import com.example.order.repository.MenuItemRepository;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;

import java.util.List;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;

@SpringBootTest
class OrderServiceIT {

    @Autowired OrderService orderService;
    @Autowired MenuItemRepository menuRepo;

    @Test
    void 正常下單_扣庫存且總額正確() {
        // 牛肉麵 x2 + 珍珠奶茶 x1（id:1 牛肉麵 150, id:3 珍奶 55）
        CreateOrderRequest req = new CreateOrderRequest();
        req.setCustomerName("小明");
        CreateOrderRequest.OrderItemRequest a = new CreateOrderRequest.OrderItemRequest();
        a.setMenuItemId(1L); a.setQuantity(2);
        CreateOrderRequest.OrderItemRequest b = new CreateOrderRequest.OrderItemRequest();
        b.setMenuItemId(3L); b.setQuantity(1);
        req.setItems(List.of(a, b));

        var order = orderService.createOrder(req);

        assertThat(order.getTotalAmount()).isEqualByComparingTo("355.00");
        assertThat(menuRepo.findById(1L).orElseThrow().getStockQuantity()).isEqualTo(18); // 20-2
        assertThat(menuRepo.findById(3L).orElseThrow().getStockQuantity()).isEqualTo(49); // 50-1
    }

    @Test
    void 庫存不足_整筆交易回滾_庫存不變() {
        MenuItem beef = menuRepo.findById(1L).orElseThrow();
        final long before = beef.getStockQuantity();

        CreateOrderRequest req = new CreateOrderRequest();
        req.setCustomerName("壓力測");
        CreateOrderRequest.OrderItemRequest item = new CreateOrderRequest.OrderItemRequest();
        item.setMenuItemId(1L);
        item.setQuantity(999);                       // 超庫存，必然失敗
        req.setItems(List.of(item));

        assertThatThrownBy(() -> orderService.createOrder(req))
                .isInstanceOf(StockNotEnoughException.class);

        // 關鍵斷言：例外之後，庫存必須與下單前相同（@Transactional 回滾了扣庫存）
        assertThat(menuRepo.findById(1L).orElseThrow().getStockQuantity())
                .isEqualTo(before);
    }
}
```

```java
package com.example.order.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.cors.CorsConfiguration;
import org.springframework.web.cors.UrlBasedCorsConfigurationSource;
import org.springframework.web.filter.CorsFilter;

import java.util.List;

@Configuration
public class CorsConfig {

    @Bean
    public CorsFilter corsFilter() {
        CorsConfiguration config = new CorsConfiguration();
        config.setAllowedOrigins(List.of(
                "http://localhost:4200",   // Angular
                "http://localhost:3000",   // React
                "http://localhost:5173"    // Vite
        ));
        config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS"));
        config.setAllowedHeaders(List.of("*"));
        config.setAllowCredentials(true);

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/api/**", config);
        return new CorsFilter(source);
    }
}
```

**controller/MenuItemController.java**（`@RestController` + `@RequestMapping("/api/menu")`）：

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET | `/api/menu` | `category`/`keyword`/`available` 三擇一優先次序（category → keyword → available → all） |
| GET | `/api/menu/{id}` | 單筆 |
| GET | `/api/menu/sold-out` | 售罄清單（**固定路徑須宣告於 `/{id}` 之前**） |
| POST | `/api/menu` | 新增（`@Valid`，成功 201） |
| PUT | `/api/menu/{id}` | 更新（`@Valid`） |
| DELETE | `/api/menu/{id}` | 刪除 |

**controller/OrderController.java**（`@RestController` + `@RequestMapping("/api/orders")`）：

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/api/orders` | 建立訂單（`@Valid`，成功 201） |

> ⚠️ **路徑順序陷阱**：把 `/sold-out`、`/dashboard` 寫在 `/{id}` 之後，會把字串當 id 轉型 → 400。固定路徑要放前面。
