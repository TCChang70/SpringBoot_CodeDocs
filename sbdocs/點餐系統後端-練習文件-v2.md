# 1. 系統情境與技術棧（教學章節）

## 1.1 業務背景

一家餐廳推出**線上點餐系統**。顧客瀏覽菜單 → 選擇項目與數量 → 成立訂單。員工需要在後台看到今天的營運狀態。

系統要解決的三個核心問題：

1. **菜單管理**：菜單項目分類、供應狀態、當日庫存要能查能改。
2. **點餐交易**：顧客下單時必須「**扣庫存 + 快照價格 + 計算總價 + 建立訂單**」，而且整個過程要麼全部成功、要麼全部失敗（**交易性**）。
3. **營運儀表板**：熱賣排行、今日營業額、待處理訂單數。

## 1.2 需求規格表（FR）

| 編號 | 功能 | 說明 | 層 |
|------|------|------|-----|
| FR-01-01 | 菜單 CRUD | 新增/查詢/編輯/刪除菜單項目 | Service/Controller |
| FR-01-02 | 菜單篩選 | 依分類、供應狀態查詢 | Repository |
| FR-01-03 | 菜單搜尋 | 依名稱關鍵字模糊搜尋（不分大小寫） | Repository |
| FR-02-01 | 建立訂單 | 扣庫存 + 快照價 + 總價 + 一筆交易完成 | Service |
| FR-02-02 | 訂單查詢 | 依 id 查詢、依狀態查詢、更新狀態 | Service/Controller |
| FR-03-01 | Dashboard | 熱賣排行 + 今日營業額 + 待處理訂單數 | Repository/Service |
| FR-03-02 | 售罄清單 | 庫存為 0 且仍上架的項目 | Repository |

## 1.3 技術棧與選擇理由

| 技術 | 版本 | 用途 | 為什麼選它 |
|------|------|------|------------|
| Java | 17 | 語言 | LTS、`record`/`var` 等現代語法 |

| Spring Data JPA | 隨 3.2 | 資料存取 | 用「方法命名」與 JPQL 取代手寫 SQL |

# 5. 資料庫設計（教學章節）

## 5.1 資料表總覽

| 表 | 用途 | 數量預期 |
|----|------|----------|
| `menu_items` | 菜單主檔（含庫存） | 6 筆種子資料 |
| `orders` | 訂單主檔 | 隨操作成長 |
| `order_items` | 訂單明細（含價格快照） | 每筆訂單至少 1 列 |

## 5.2 實體關係圖（ER）

```
menu_items 1 ══< ∞ order_items >══ 1 orders
   │  id                    │ id          │ id
   │  name (80)             │ order_id FK  │ customer_name (50)
   │  category (30)         │ menu_item_id │ order_time (DATETIME)
   │  price DECIMAL(10,2)   │ quantity     │ status (PENDING/COMPLETED/CANCELLED)
   │  is_available          │ unit_price   │ total_amount DECIMAL(10,2)
   │  stock_quantity        │ (快照)        │
```

設計重點：

1. `order_items.unit_price` 是**建立訂單當下的價格快照**。菜單日後調價，不影響歷史訂單金額。
2. `orders.total_amount` 在建單時由系統累加計算，避免每次查詢重算。
3. FK 都在 `order_items`（多那一側）：`order_id → orders.id`、`menu_item_id → menu_items.id`。

## 5.3 schema.sql（指定內容，直接建立）

```sql
-- menu_items：菜單主檔
CREATE TABLE IF NOT EXISTS menu_items (
    id             BIGINT AUTO_INCREMENT PRIMARY KEY,
    name           VARCHAR(80)  NOT NULL,
    category       VARCHAR(30)  NOT NULL,
    price          DECIMAL(10,2) NOT NULL,
    is_available   TINYINT(1)   NOT NULL DEFAULT 1,
    stock_quantity INT          NOT NULL DEFAULT 0
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- orders：訂單主檔
CREATE TABLE IF NOT EXISTS orders (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    customer_name VARCHAR(50)  NOT NULL,
    order_time    DATETIME     NOT NULL,
    status        VARCHAR(20)  NOT NULL DEFAULT 'PENDING',
    total_amount  DECIMAL(10,2) NOT NULL DEFAULT 0.00
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- order_items：訂單明細
CREATE TABLE IF NOT EXISTS order_items (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    order_id      BIGINT         NOT NULL,
    menu_item_id  BIGINT         NOT NULL,
    quantity      INT            NOT NULL,
    unit_price    DECIMAL(10,2)  NOT NULL,
    CONSTRAINT fk_oi_order FOREIGN KEY (order_id)     REFERENCES orders(id),
    CONSTRAINT fk_oi_menu  FOREIGN KEY (menu_item_id) REFERENCES menu_items(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

> ⚠️ 為什麼價錢用 `DECIMAL(10,2)` 而不是 `double`？浮點數在加減乘除會有誤差（例如 0.1+0.2），金錢不允許誤差，一律用**定點小數**。

# 6. 實體設計 Entity（練習章節）

## 6.1 概念講解

Entity 是把「資料表」對應到「Java 物件」的橋樑。三個常用註解：

| 註解 | 作用 |
|------|------|
| `@Entity` | 標記這是被 JPA 管理的實體 |
| `@Table(name = "...")` | 對應哪張資料表（不加就用類別名） |
| `@Column(...)` | 欄位名與約束（nullable / length） |

關聯註解：

| 註解 | 意義 | 例子 |
|------|------|------|
| `@ManyToOne` | 多對一 | 多筆明細 → 一張訂單；多筆明細 → 一筆菜單 |
| `@OneToMany(mappedBy=...)` | 一對多 | 一張訂單 → 多筆明細（**反向端**） |
| `cascade = CascadeType.ALL` | 存父就存子 | 存訂單時明細一起存 |
| `orphanRemoval = true` | 子從集合移除就刪 | 移除明細連帶刪列 |

> ⚠️ 一對多時 `mappedBy` 的值，是**多那一側持有關聯的欄位名稱**（例如 `OrderItem` 上的 `order` 欄位），而不是資料表欄位。

## 6.2 範例：MenuItem（完整示範，請照抄並理解）

```java
package com.example.order.model;

import jakarta.persistence.*;
import java.math.BigDecimal;

@Entity
@Table(name = "menu_items")
public class MenuItem {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "name", nullable = false, length = 80)
    private String name;

    @Column(name = "category", nullable = false, length = 30)
    private String category;

    @Column(name = "price", nullable = false)
    private BigDecimal price;

    @Column(name = "is_available")
    private boolean available = true;

    @Column(name = "stock_quantity")
    private int stockQuantity;

    // Getter / Setter
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public String getCategory() { return category; }
    public void setCategory(String category) { this.category = category; }
    public BigDecimal getPrice() { return price; }
    public void setPrice(BigDecimal price) { this.price = price; }
    public boolean isAvailable() { return available; }
    public void setAvailable(boolean available) { this.available = available; }
    public int getStockQuantity() { return stockQuantity; }
    public void setStockQuantity(int stockQuantity) { this.stockQuantity = stockQuantity; }
}
```

觀察重點：`@GeneratedValue(strategy = IDENTITY)` 對應 MySQL 的 `AUTO_INCREMENT`。

## 6.3 練習：Order（填空 ①）

`orders` 表沒有實際的 FK 欄位，因為它是「一」那一側。它的 `items` 集合用 `@OneToMany` 映射：

```java
package com.example.order.model;

import jakarta.persistence.*;
import java.math.BigDecimal;
import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.List;

@Entity
@Table(name = "orders")
public class Order {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "customer_name", nullable = false, length = 50)
```

# 7. Repository 層（練習章節）

## 7.1 概念講解

`JpaRepository<Entity, Id>` 幫你實作所有 CRUD（`findAll`、`findById`、`save`、`delete`）。額外的查詢有兩種寫法：

| 方式 | 何時用 | 例子 |
|------|--------|------|
| **Derived Query** | 條件簡單、欄位單一 | `findByCategory`、`findByAvailableTrue` |
| **@Query JPQL** | 需要 JOIN、GROUP BY、LIKE、函數 | 關鍵字搜尋、分類統計 |

> JPQL 是「操作 Entity 的物件語言」，欄位名用 Java 屬性名（如 `m.name`）而不是資料表欄位。

## 7.2 範例：MenuItemRepository（填空 ⑤⑥）

大部分完整示範，僅 `searchByName`（⑤）與 `getCategorySalesSummary`（⑥）留白：

```java
package com.example.order.repository;

import com.example.order.model.MenuItem;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

import java.util.List;

public interface MenuItemRepository extends JpaRepository<MenuItem, Long> {

    // Derived Query：只要「方法命名」符合規則就自動實作
    List<MenuItem> findByCategory(String category);

    // 布林條件的慣例：findBy<Field>True / False
    List<MenuItem> findByAvailableTrue();

    // 多條件：庫存恰為 0 且仍上架（售罄清單 FR-03-02）
    List<MenuItem> findByStockQuantityAndAvailableTrue(int stockQuantity);

    // @Query JPQL：姓名模糊搜尋 → FR-01-03（填空 ⑤）
    @Query("SELECT m FROM MenuItem m WHERE ⑤ ________")
    List<MenuItem> searchByName(@Param("keyword") String keyword);

    // 熱賣排行：依總銷量排序，回傳 (名稱, 總數量)
    @Query("SELECT m.name, SUM(oi.quantity) FROM OrderItem oi " +
           "JOIN oi.menuItem m GROUP BY m.id, m.name " +
           "ORDER BY SUM(oi.quantity) DESC")
    List<Object[]> findTopSellingItems();

    // 各分類銷售統計 → FR-03-01（填空 ⑥）
    @Query("SELECT ⑥ ________ FROM OrderItem oi " +
           "JOIN oi.menuItem m GROUP BY m.category " +
           "ORDER BY SUM(oi.quantity) DESC")
    List<Object[]> getCategorySalesSummary();
}
```

### 重點解說

- **`⑤` 關鍵字搜尋**：使用 `LOWER(m.name) LIKE LOWER(CONCAT('%', :keyword, '%'))`。
  把兩邊都轉小寫再比對 → 不分大小寫；`CONCAT` 組 `%關鍵字%` → 模糊。
- **`⑥` 分類統計**：SELECT 要帶「分組依據（`m.category`）＋三個聚合（`COUNT`、`SUM(quantity)`、`SUM(unitPrice×quantity)`）」；
  沒有出現在 GROUP BY 的欄位不能直接 SELECT。
- **`JOIN oi.menuItem m`**：JPQL 連到關聯物件，走 `OrderItem → MenuItem`。

# 8. DTO 設計（練習章節）

## 8.1 概念講解

DTO（Data Transfer Object）是「API 進出的資料形狀」，跟 Entity 分開的好處：

1. **不直接暴露 Entity**（避免把內部欄位全部丟出去）。
2. **前後端解耦**：資料庫改了，API 形狀可以不動。
3. **放驗證註解**（`@NotBlank` / `@Size` / `@DecimalMin`），把檢查集中在此層。

統一包裝 `ApiResponse<T>`：

| 欄位 | 型別 | 說明 |
|------|------|------|
| success | boolean | 是否成功 |
| message | String | 訊息 |
| data | T | 實際資料（失敗時通常為 null） |

## 8.2 範例：ApiResponse（完整示範）

```java
package com.example.order.dto;

public class ApiResponse<T> {

    private boolean success;
    private String  message;
    private T       data;

    public static <T> ApiResponse<T> ok(T data) {
        ApiResponse<T> res = new ApiResponse<>();
        res.success = true;
        res.message = "success";
        res.data    = data;
        return res;
    }

    public static <T> ApiResponse<T> ok(String message, T data) {
        ApiResponse<T> res = new ApiResponse<>();
        res.success = true;
        res.message = message;
        res.data    = data;
        return res;
    }

    public boolean isSuccess() { return success; }
    public void setSuccess(boolean success) { this.success = success; }
    public String getMessage() { return message; }
    public void setMessage(String message) { this.message = message; }
    public T getData() { return data; }
    public void setData(T data) { this.data = data; }
}
```

# 9. Service 層（練習章節）

## 9.1 概念講解

Service 是商業邏輯的家。兩個核心觀念：

### @Transactional（交易）

> 把一組動作包成「**全部成功或全部失敗**」。

```java
@Transactional
public Order createOrder(...) {
    // 步驟1 扣庫存
    // 步驟2 建明細
    // 步驟3 存訂單
}
```

任一步驟拋 `RuntimeException` 且未被捕獲 → **整段回滾**（已執行的 UPDATE 全部還原）。
查詢用 `@Transactional(readOnly = true)` 告訴 JPA「不鎖、快取優化」。

### 職責分配

| 誰 | 做什麼 |
|----|--------|
| Controller | HTTP 轉譯、參數綁定 |
| Service | 業務規則、交易、協調 Repository |
| Repository | 資料存取 |

## 9.2 範例：MenuItemService（完整參照，不填空）

# 10. Controller 層（練習章節）

## 10.1 概念講解

Controller 只做四件事：**接參數 → 叫 Service → 包 ApiResponse → 回狀態碼**。

路徑命名慣例：

- 集合用複數：`/api/menu`、`/api/orders`
- 單筆用 `/api/xxx/{id}`
- 動作子路徑：`/api/menu/sold-out`、`/api/orders/dashboard`

> ⚠️ **路徑順序陷阱**：`/api/menu/{id}` 會去吃任何單段路徑。
> 所以 **固定路徑（`sold-out`、`dashboard`）必須宣告在 `/{id}` 之前**。

# 11. 全域例外處理（練習章節）

## 11.1 概念講解

`@RestControllerAdvice` 是「全域例外攔截器」：Method 拋出的例外會被集中處理，
讓 API 統一回傳錯誤格式，而不是直接噴 500 stack trace。

| 例外 | HTTP | errorCode |
|------|------|-----------|
| `ResourceNotFoundException` | 404 | NOT_FOUND |
| `StockNotEnoughException` | 400 | STOCK_NOT_ENOUGH |
| `IllegalArgumentException` | 400 | BAD_REQUEST |
| `MethodArgumentNotValidException`（@Valid 失敗） | 400 | VALIDATION_ERROR（含各欄位錯誤） |

```java
// src/main/java/com/example/order/exception/GlobalExceptionHandler.java
package com.example.order.exception;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.util.HashMap;
import java.util.Map;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<Map<String, Object>> handleNotFound(ResourceNotFoundException ex) {
        return buildError(HttpStatus.NOT_FOUND, "NOT_FOUND", ex.getMessage());
    }

    // 填空 ⑰：為 StockNotEnoughException 註冊 handler → 400 + STOCK_NOT_ENOUGH
    @⑰ ________(StockNotEnoughException.class)
    public ResponseEntity<Map<String, Object>> handleStock(StockNotEnoughException ex) {
        return buildError(HttpStatus.BAD_REQUEST, "STOCK_NOT_ENOUGH", ex.getMessage());
    }

    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<Map<String, Object>> handleBadRequest(IllegalArgumentException ex) {
        return buildError(HttpStatus.BAD_REQUEST, "BAD_REQUEST", ex.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, Object>> handleValidation(MethodArgumentNotValidException ex) {
        Map<String, String> fieldErrors = new HashMap<>();
        for (FieldError fe : ex.getBindingResult().getFieldErrors()) {
            fieldErrors.put(fe.getField(), fe.getDefaultMessage());
        }
        Map<String, Object> body = new HashMap<>();
        body.put("success", false);
        body.put("errorCode", "VALIDATION_ERROR");
        body.put("errors", fieldErrors);
        return ResponseEntity.badRequest().body(body);
    }

    private ResponseEntity<Map<String, Object>> buildError(
            HttpStatus status, String errorCode, String message) {
        Map<String, Object> body = new HashMap<>();
        body.put("success", false);
        body.put("errorCode", errorCode);
        body.put("message", message);
        return ResponseEntity.status(status).body(body);
    }
}
```
